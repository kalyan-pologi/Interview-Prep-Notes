🛠️ Useful DevOps Commands

Docker + Kubernetes + Minikube useful commands.

Docker, core daily commands

docker ps                      # List running containers
docker ps -a                   # List all containers (including stopped)
docker images                  # List downloaded images
docker build -t app:latest .   # Build image from Dockerfile
docker run -d -p 8080:8080 app # Run container in background
docker stop <id>               # Stop running container
docker rm <id>                 # Remove stopped container
docker logs -f <id>            # View live logs
docker exec -it <id> bash      # Enter container shell
docker-compose up -d           # Start all services from docker-compose.yml
docker-compose down            # Stop and remove all containers
docker system prune -a --volumes  # Full cleanup (use carefully)

Kubernetes, most used daily

kubectl get pods -n microservices        # List pods
kubectl get svc -n microservices         # List services
kubectl logs -f <pod> -n microservices   # Stream logs
kubectl exec -it <pod> -n microservices -- bash   # Shell into pod
kubectl apply -f k8s/                    # Deploy all YAML files
kubectl delete -f k8s/                   # Remove all resources
kubectl get ingress -n microservices     # Check ingress routes
kubectl describe pod <pod> -n microservices  # Debug pod issues
kubectl get events --sort-by=.metadata.creationTimestamp  # Recent events
kubectl scale deployment <name> --replicas=3 -n microservices # Scale up/down
kubectl rollout restart deployment/<name> -n microservices   # Restart deployment
kubectl top pods -n microservices          # Resource usage (CPU/mem)
kubectl get all -n microservices           # Quick overview of everything

Minikube, local cluster essentials

minikube start --driver=docker        # Start local Kubernetes
minikube stop                         # Stop cluster
minikube delete                       # Delete cluster completely
minikube addons enable ingress        # Enable Ingress controller
minikube tunnel                       # Expose ingress (keep this running)
minikube ip                           # Show cluster IP
minikube dashboard                    # Open K8s dashboard
minikube service api-gateway -n microservices --url  # Get service URL
minikube image build -t user-service:latest .        # Build image inside cluster

Daily workflow summary

# 1. Start environment
minikube start --driver=docker
minikube addons enable ingress

# 2. Deploy project
kubectl apply -f k8s/

# 3. Check resources
kubectl get pods -n microservices
kubectl get svc -n microservices
kubectl get ingress -n microservices

# 4. Debug & monitor
kubectl logs -f <pod> -n microservices
kubectl exec -it <pod> -n microservices -- bash
minikube dashboard

# 5. Stop or reset
kubectl delete -f k8s/
minikube stop

Twelve-Factor App Principles

A set of practices for building cloud-native, horizontally scalable applications, codebase in version control, dependencies explicitly declared, config kept in the environment rather than the code, backing services treated as attached resources, strict separation of build/release/run stages, processes kept stateless, services exported via port binding, scaling out through process concurrency, fast startup and graceful shutdown (disposability), dev/prod parity, logs treated as event streams rather than files, and admin tasks run as one-off processes.

Logging Practices, Dev to Prod

Logging needs change as a service moves toward production, verbose debug logging locally, structured JSON logs with correlation/trace IDs in staging and prod so logs can be tied back to a specific request across services, log levels that can be adjusted without a redeploy, and aggregation into a central system rather than reading logs off individual containers.

Security Practices

Baseline practices across the pipeline, secrets kept out of source control and pulled from a secrets manager at runtime, least-privilege IAM roles per service, image scanning in CI before a build is allowed to deploy, network policies restricting which services can talk to which, and regular dependency updates to close known vulnerabilities.

Root Cause Analysis

When a production incident happens, the goal of RCA is identifying the actual underlying cause rather than just the symptom that paged someone, categories worth checking include code defects, configuration drift between environments, infrastructure/capacity limits, third-party dependency failures, and deployment/rollout issues. A good RCA documents the timeline, the detection method, the fix, and a concrete follow-up action to prevent recurrence.
