React core concepts, quick reference.

Function vs. Class Components

Function components are the modern, recommended approach: simpler syntax, use Hooks (useState, useEffect, etc.), no this keyword, easier to read, test, and reuse logic.

Class components are the older style: use lifecycle methods (componentDidMount, componentDidUpdate, componentWillUnmount), use this.state and this.setState(), more boilerplate, rarely needed since Hooks landed in React 16.8.

Components & JSX

Components are reusable UI pieces that encapsulate structure, logic, and styling. JSX is the HTML-like syntax extension used to describe what they render.

State (useState)

Mutable data that triggers a re-render when it changes.

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
    </>
  );
}

useEffect

Handles side effects, data fetching, subscriptions, timers, cleanup.

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => setUser(data));
  }, [userId]);

  return <div>{user?.name}</div>;
}

Forms & Controlled Components

function LoginForm() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault();
    // handle login
  };

  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={e => setEmail(e.target.value)} />
      <input type="password" value={password}
        onChange={e => setPassword(e.target.value)} />
      <button type="submit">Login</button>
    </form>
  );
}

useContext

Shares data across components without passing props down through every intermediate level (prop drilling).

const ThemeContext = createContext();

function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Header />
      <Content />
    </ThemeContext.Provider>
  );
}

function Header() {
  const { theme, setTheme } = useContext(ThemeContext);
  return <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>
    Toggle Theme
  </button>;
}

Custom Hooks

Reusable functions that extract stateful component logic so it can be shared.

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch(url)
      .then(res => res.json())
      .then(data => {
        setData(data);
        setLoading(false);
      });
  }, [url]);

  return { data, loading };
}

useMemo, useCallback, useReducer

useMemo memoizes a computed value, useCallback memoizes a function reference, both exist purely to avoid unnecessary recalculation or re-renders in child components. useReducer is a useState alternative for complex state logic, where the next state depends on the previous state or involves multiple sub-values.

function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
    default: return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return (
    <>
      <p>Count: {state.count}</p>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
    </>
  );
}

useRef

Accesses DOM elements directly, or stores a mutable value that persists between renders without triggering a re-render when it changes. Common uses: focusing an input, integrating a third-party library, storing a previous value for comparison.

function TextInput() {
  const inputRef = useRef(null);
  const countRef = useRef(0);

  const focusInput = () => { inputRef.current.focus(); };

  useEffect(() => {
    countRef.current += 1; // does not trigger re-render
  });

  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </>
  );
}

Rules of Hooks

  1. Top level only, never call hooks inside loops, conditions, or nested functions
  2. React functions only, only call hooks from React components or custom hooks
  3. Consistent order, hooks must run in the same order every render for React to track state correctly
// Wrong
if (condition) {
  useState(0); // conditional hook call
}

// Correct
const [count, setCount] = useState(0);
if (condition) {
  setCount(1); // use the hook's result conditionally, not the hook call itself
}

Node vs. Element vs. Component

  • React Node, anything renderable, a string, number, element, array, null, or boolean
  • React Element, a plain JavaScript object describing what should appear on screen, created by JSX or React.createElement
  • React Component, a function or class that returns React elements, the reusable building block

State Mutation Problems

React compares state using reference equality (Object.is). Mutating an object in place keeps the same reference, so React thinks nothing changed and skips the re-render, leaving the UI stale. Always create a new object or array reference instead.

// Wrong, mutates in place
const handleUpdate = () => {
  user.name = 'John';
  setUser(user); // same reference, no re-render
};

// Correct, new reference
const handleUpdate = () => {
  setUser({ ...user, name: 'John' });
};

setItems([...items.slice(0, index), updatedItem, ...items.slice(index + 1)]);

Reconciliation & Keys

React diffs the new virtual DOM tree against the previous one to find the minimal set of real DOM changes. Same element type at the same position preserves the component instance and its state, a different type tears it down and creates a new one. Keys let React match list items across renders so reordering or removing an item does not re-render the entire list.

// without keys, inefficient
{items.map(item => <Item data={item} />)}

// with keys, efficient
{items.map(item => <Item key={item.id} data={item} />)}

Higher-Order Components

A function that takes a component and returns an enhanced version with additional props or behavior. Common uses: authentication gating, logging, data fetching, theme injection.

const withAuth = (Component) => (props) => {
  const { isAuthenticated } = useAuth();
  return isAuthenticated ? <Component {...props} /> : <Login />;
};

const ProtectedDashboard = withAuth(Dashboard);

Performance Optimization

  • Memoization, React.memo, useMemo, useCallback to skip unnecessary re-renders and recalculations
  • Code splitting, dynamic imports with React.lazy and Suspense, splits the bundle into smaller chunks so the browser only loads what the current route or view actually needs
  • Bundle optimization, tree shaking, watching bundle size, avoiding unnecessarily large dependencies
