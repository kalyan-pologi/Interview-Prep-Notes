✅ JUnit Core Concepts

Definitions and use cases for JUnit testing.

Test Methods & Assertions

A test method is annotated with @Test and contains the logic and assertions that verify expected behavior, for example @Test void testAdd() { assertEquals(5, calculator.add(2, 3)); }. Common assertions:

  • assertEquals(expected, actual), compare values
  • assertTrue(condition) / assertFalse(condition), boolean checks
  • assertNull(object) / assertNotNull(object), null checks
  • assertThrows(Exception.class, () -> method()), exception testing

Test Lifecycle

Annotations controlling when setup and cleanup run:

  • @BeforeEach, runs before each test
  • @AfterEach, runs after each test
  • @BeforeAll, runs once before all tests, must be static
  • @AfterAll, runs once after all tests, must be static

Common pattern: @BeforeEach void setup() { db.createTables(); } paired with @AfterEach void cleanup() { db.clearData(); } to keep tests isolated from each other.

Parameterized Tests

Runs the same test logic against different input values using @ParameterizedTest, avoiding copy-pasted near-duplicate test methods:

  • @ValueSource(ints = {1, 2, 3, 4}), multiple simple inputs
  • @CsvSource({"1,1,2", "2,3,5"}), CSV-style multi-argument inputs
  • @MethodSource("testData"), pulls test data from a method
@ParameterizedTest
@ValueSource(strings = {"test@email.com", "user@domain.org"})
void testValidEmails(String email) {
    assertTrue(validator.isValid(email));
}

Mocking with Mockito

Mockito creates mock objects to isolate the unit under test from its dependencies.

  • @Mock, creates a mock object
  • @InjectMocks, injects the mocks into the class under test
@Mock PaymentService paymentService;
@InjectMocks OrderService orderService;

when(paymentService.process(any())).thenReturn(true);
verify(emailService).send("test@email.com");

Test Organization

  • @Tag("unit"), @Tag("integration"), tag tests for selective runs
  • @Suite + @SelectClasses({Test1.class, Test2.class}), group into suites
  • @SelectPackages("com.example.tests"), select by package

Exception Testing

assertThrows(IllegalArgumentException.class, () -> divide(5, 0));
assertThrows(UnauthorizedException.class, () -> deleteUser());

Integration Testing

Beyond isolated unit tests, Spring Boot provides slice tests for testing component interaction with real infrastructure:

  • @DataJpaTest, tests the repository/database layer only
  • @WebMvcTest, tests the web/controller layer only, with mocked service beans
  • @SpringBootTest, loads the full application context

Performance Testing

@Timeout(value = 5, unit = TimeUnit.SECONDS) fails a test if it takes longer than the given duration, useful for catching accidental performance regressions or hangs.

Quick Reference

class UserServiceTest {
    @BeforeEach
    void setUp() { /* setup */ }

    @Test
    void shouldCreateUser() {
        // Given
        String name = "John";
        // When
        User user = userService.create(name);
        // Then
        assertNotNull(user);
        assertEquals(name, user.getName());
    }

    @ParameterizedTest
    @ValueSource(strings = {"", " ", "null"})
    void shouldRejectInvalidNames(String invalidName) {
        assertThrows(IllegalArgumentException.class,
            () -> userService.create(invalidName));
    }
}

Maven / Gradle test commands:

# Maven
mvn test                    # Run all tests
mvn test -Dtest=UserTest    # Run specific test
mvn test -Dgroups=unit      # Run tagged tests

# Gradle
./gradlew test                 # Run all tests
./gradlew test --tests UserTest # Run specific test
