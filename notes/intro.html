Your roles and responsibilities

As a developer at Reidy.AI, my work covers four areas. On appraisal, I designed a dual persistence architecture with two write paths, an auditable credit charged history and a reusable free cache, and I isolated them at the module level using two separate Spring Boot starter libraries. I wrote a normalizer that maps the residential and commercial valuation engines into one shared schema, and I extracted the valuation logic into a shared service, verified with before and after regression tests in JUnit and Mockito. On Mashvisor, I built a Spring WebFlux caching layer over the third party API as a Decorator around one shared transport interface, with a TTL per endpoint and upserts to handle concurrent writes. On notifications, I handle event driven delivery over Azure Service Bus topics and subscriptions, so Email, SMS and In-App handlers run asynchronously, with templates cached in Redis. On chat, I built the WebSocket based messaging from scratch and own it in production, including performance tuning and fixes for concurrent message sends. Across all four, my focus is on reliability, data correctness and keeping the services loosely coupled and easy to scale.

How and where you used Java and Spring Boot in the current project

On the Java side, I used collections, streams, lambdas and Optional to keep the logic clean and readable, and ExecutorService and CompletableFuture to run independent work in parallel so request latency stays low. On the Spring Boot side, I started each service from starters and auto-configuration, which saved a lot of boilerplate, and used dependency injection to keep the controller, service and repository layers decoupled. I built REST endpoints with @RestController, checked incoming payloads with Bean Validation, and routed all exceptions through a single @ControllerAdvice so error responses stayed consistent. For persistence, I used Spring Data JPA on Azure SQL Server, with @Transactional keeping related writes atomic. When a call to an outside service shouldn't hold a thread, I used Spring WebFlux and WebClient, working with Mono and Flux. For background and event driven work, I used Spring Boot listeners that consume messages from Azure Service Bus, and Redis to absorb repeated reads. I handled access control with Spring Security, OAuth2 and JWT, and used Spring profiles to run the same build across dev, test and production settings. I covered the code with JUnit and Mockito tests, and used Actuator endpoints and logs to spot problems early.
